The week's stakes

UX is where AI's biggest lie lives: confident personas, quotes from users who don't exist, statistics from studies that never happened. Fake research is worse than no research — it carries authority without evidence.

The professional split

AI for structure and pessimism (assumptions, flows, edge cases, microcopy). Research for evidence and empathy (what's actually true of real people). AI can imagine your users; only research can know them — label which one you're holding.

02Key Concepts

1 · Synthetic users vs. real research

AI-invented users are hypotheses wearing name tags — useful exactly as hypotheses (they force assumptions into the open), poison the moment anyone treats them as findings.

  • Label every persona: HYPOTHESIS — needs real research.
  • For each persona claim, write the interview question that would test it.
  • Never present synthetic users as research. That's fabrication, and it gets discovered.

2 · The assumption audit: the cheapest UX win

Before any design: "list every assumption hiding in this idea," then sort — safe to assume / must research / dangerous to guess. Ten minutes that reorder a project. This is AI at its best: pessimistic structure, no facts required.

3 · Flows: the happy path is the easy 20%

AI drafts a clean flow in seconds. The value move is the next prompt: "now give me the unhappy paths." Bad photo, no signal, ambiguous result, abandoned mid-task. Models are surprisingly good at enumerating failure — they've read every support forum on earth. Most of real UX is designing the recovery.

4 · Wireframes: ugly on purpose

Grey boxes, real structure, real microcopy. Polish hides thinking — yours and the model's. AI writes the wireframe text (each screen's purpose, elements, exact button labels, empty states); you draw the boxes. Microcopy is a real deliverable: error messages are where products feel human or hostile.

Watch out

AI-generated visual UI looks finished and thinks nothing. Wireframes stay grey this week. App-builders return in Week 11 — with inspection habits.

5 · The Edge Case Hunt: pessimism as a service

After any flow: "8 edge cases ranked by how badly each damages trust." Then accessibility made specific — not "be accessible" but this flow's risks (photo capture with low vision, colour-only status, touch targets in gloves) — verified against WCAG, because models paraphrase guidelines loosely.

6 · From plan to prototype

flow → wireframe text → boxes → clickable path. AI accelerates every document before the canvas; the canvas is still judgment.

05Step-by-Step Workflows

The five-prompt UX planning kit (~45 min for any idea)

  1. Audit assumptions → sort three ways.
  2. Hypothesize 2 personas → label → write their test questions.
  3. Flow the core task → demand unhappy paths.
  4. Wireframe text per screen → exact microcopy → you box it.
  5. Attack: edge cases ranked by trust damage + flow-specific accessibility → verify against WCAG.

Wireframe from text (paper or Figma)

  1. Take one screen's wireframe text.
  2. Draw the boxes top to bottom — 5 minutes, ugly.
  3. Write the microcopy into the boxes — real labels, not lorem.
  4. Mark ⚠ any element you overruled — your judgment trail.
  5. Connect the happy path; add one unhappy-path branch.

06Prompt Recipes

1 · The assumption auditI want to design "[vague idea]". Before any design: list every assumption hiding in that sentence — about users, problems, context, and devices. Then sort them into three groups: safe to assume / must research / dangerous to guess. Don't design anything yet.
2 · Personas as hypothesesDraft 2 contrasting persona HYPOTHESES for this idea. Label each clearly as "UNVALIDATED HYPOTHESIS". For each: context, the frustration that brings them here, their moment of need, and what they'd never do in an app. Then write the 5 interview questions that would test whether each persona is real.
3 · The flow with unhappy pathsCore task: "[the one job]". Write the task flow step by step. Then add 3 unhappy paths ([likely failures — bad input, no connection, ambiguous result]) and how the user recovers from each without a dead end.
4 · Wireframe text + microcopyDescribe a [5]-screen low-fi wireframe for this flow, in text. Each screen: its single purpose, key elements top to bottom, and the EXACT microcopy for buttons, error messages, and empty states. Grey boxes only — no visual styling, no colours, no branding.
5 · The edge case hunt + accessibilityNow attack this flow: list 8 edge cases or failure states we haven't handled, ranked by how badly each damages user trust. Then write an accessibility checklist specific to THIS flow (not generic WCAG boilerplate): the real risks for [photo capture / colour-coded status / outdoor use / screen readers] in this design.
Bonus · The microcopy de-roboterRewrite this microcopy in a voice that is [calm, plain, slightly warm]: [paste]. Rules: no exclamation marks, no "oops", no blame, every error says what happened and what to do next, reading age ~12.

07Lab: Edge Case Hunt (70 min)

Cold start friendly. No idea? Standing brief: an app that helps housemates fairly split chores without becoming the chore police.

  1. Kit prompts 1–3 (20 min): audit → labelled personas with test questions → flow with unhappy paths.
  2. Wireframe (20 min): prompt 4 for the text, then box it yourself — paper or Figma, 5 screens, microcopy written in, ⚠ marks where you overruled.
  3. The Hunt (15 min): prompt 5 → pick the 3 edge cases that most damage trust → amend your flow/wireframe to handle them. The amendment is the assessed thinking.
  4. Critique checklist (15 min): 6 lines (Week 2 method) from your brief + edge cases. Test against your own wireframe — at least one line should fail.
Zero-AI path (fully equal)

The question structures run beautifully on paper with a partner playing pessimist. Microcopy written by hand. Same deliverables, equal credit.

08Integrity Check

This week's four
  1. Is every persona still wearing its HYPOTHESIS label — everywhere it travels?
  2. Did any "users want…" sentence sneak in without a source? Kill it or mark it.
  3. Accessibility claims: checked against actual WCAG, or model paraphrase?
  4. Portfolio language: "Research direction AI-assisted; all user claims are labelled hypotheses pending research." Honesty reads as method maturity.

09Troubleshooting

ProblemFix
Personas feel so plausibleThat's the danger. Plausibility ≠ truth. Read the label aloud; write the test questions
Flow is suspiciously cleanYou got the happy path. Demand the unhappy paths — that's where the design is
Wireframe text wants to be pretty"Grey boxes only, no styling" — repeat; fresh chat if it persists
Microcopy sounds like a chatbotRun the de-roboter; ban "oops" by name
Edge cases are generic ("slow internet")Demand specificity to YOUR flow: "edge cases unique to photo-diagnosing plants outdoors"
Figma overwhelmsPaper. Genuinely. The thinking is identical and faster today

Optional extension

  • Take your 5 persona test questions and interview one real person (a housemate counts). Note every place reality disagreed — that delta is what research is for.
